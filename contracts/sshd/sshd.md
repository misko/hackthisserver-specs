# SSH public-key command and terminal contract

Identity: sshd-r2. Document agreement Draft; implementation evidence Untested for every S requirement. Owner: future SSH maintainer; user owns product decisions. Fresh specification proposal, not a preserved historical deployment or complete OpenSSH feature claim. [Research](research.md), [census](security.md#core-original-record-disposition-census), [approaches/capabilities](research.md#approaches-and-capabilities), [acceptance](acceptance.md), [tasks](acceptance.md#future-tasks) and [decision ledger](../decisions.md) identify scope and gaps. S-01 through S-16 each map to identically numbered A-S scenario and a future task.

Intended workload is many hostile unauthenticated attempts and at most one authenticated user performing an operator-authorized command or terminal session. Proposed platform is Linux x86-64 ELF with one operator-selected unprivileged account, operator-provided public authorization keys and server host keys. Proposed compatibility is SSH version 2 wire behavior for the selected profile, not OpenSSH configuration, CLI, modules, key-management convenience features or SFTP. Proposed reference OpenSSH Portable 10.6p1 is pinned to a8c72b842423f0774f542d3c2197247c3dd28d74 with matching allowed algorithms, one-user authority and resource allowances. No reference/candidate was built or run.

## Authority, required capabilities and denials

Required: host-authenticated encrypted SSH transport, public-key proof of possession for selected account, one authenticated transport and one session channel at a time, exec and shell requests, stdin/stdout/stderr, exact exit status/signal, PTY/modes/resize, EOF/close/cancellation, rekey, startup/reload/revocation/drain and finite overload recovery. One authenticated connection/channel is a new proposed capacity policy; the recipe's at-most-one-authenticated-user requirement is not generalized into many-user testing.

Proposed algorithms: curve25519-sha256 and diffie-hellman-group14-sha256 KEX; ssh-ed25519 and rsa-sha2-256/rsa-sha2-512 host/user signatures; aes128-ctr and aes256-ctr encryption; hmac-sha2-256 integrity; compression none. RSA public-key blobs retain the standard ssh-rsa key encoding while SHA-1 signatures are excluded. Strict KEX is supported with both standard and pre-standard matching marker pairs from pinned draft-ietf-sshm-strict-kex-02, work in progress; this profile proposes requiring a negotiated matching pair before authentication. RFC 8308 server-sig-algs must accurately advertise supported signatures. The finite algorithm set and strict-only compatibility require user agreement; mandatory current standards and errata remain researcher obligations. SSH-R5 mandatory implementation coverage is integrated in the unagreed crypto-r3 SSH mandatory profile while the modern negotiated allowlist stays unchanged, using RFC4251 local policy. The staged rationale remains linked in [proposal history](research.md#mandatory-implementation-rationale); no user adoption or runtime conformance follows. SSH-R6 exposed conflicting window accounting; the final researched disposition follows verified erratum 3878 explicitly, with pinned-reference divergence retained as an interoperability risk and future observer control. Neither finding is permission to execute anything.

Excluded authentication: password, keyboard-interactive, PAM, GSSAPI, host-based, user certificates, hardware/security-key extensions and agent-mediated server authority. Unsupported methods fail with only publickey advertised, never partial success. Excluded protocol capabilities: direct/remote/dynamic TCP forwarding, Unix-socket forwarding, X11, agent forwarding, tunnels, SFTP/other subsystem requests, environment injection, concurrent additional session channels and remote administration. Want-reply requests receive failure, unknown/denied channel opens receive SSH_OPEN_ADMINISTRATIVELY_PROHIBITED, and no forbidden listener/contact/terminal/workload is created. Requests with want-reply false receive no unsolicited failure. Unsupported initial version/algorithm ends the connection with bounded appropriate error, never downgrade to SSH 1 or TLS.

Authorized commands intentionally have the selected account's OS permissions, including its ordinary filesystem/network/program authority. Denying protocol forwarding/subsystem requests does not promise that an authorized command cannot access files, make network calls or invoke a user-installed program. Command programs are declared user workloads, not concealed implementations of server TLS/SSH/authentication. Operator provisioning must keep host private keys and daemon-only secrets outside command-account access and tracing authority. This account/OS boundary is pending; no root compromise or malicious kernel/administrator resistance is claimed.

Execution-qualification prerequisite S-OS-01, revised in this unagreed draft (owner future SSH maintainer, scenario A-S-07, tasks S-T2/S-T4, evidence Untested): the operator supplies enforceable membership of all service-granted workload descendants, authority to terminate that complete workload despite concurrent forks/detachment, and protection against account escape or modification of its enclosing authority. Host keys/daemon secrets remain outside the account's read/trace authority. A host unable to supply these properties is unsupported and cannot become ready. No particular containment API, process layout or private algorithm is prescribed. [Linux's documented whole-domain termination and independent population observation](https://docs.kernel.org/admin-guide/cgroup-v2.html) establish relevant platform responsibilities; they do not supply a bounded completion guarantee for arbitrary kernel/device waits. No inspected CLI host is asserted to meet this prerequisite.

### S-07 cleanup profile and continuing responsibility

This section refines S-07/S-OS-01 and explicitly replaces draft-r1's impossible generic five-second all-descendant termination assertion. User-endorsed direction is Y=5 s for at least 99% **observed normal** completions and X=30 s for all normal completions, with diagnosed exceptional residual work still charged and escalated. These are draft qualification defaults, not measured population probabilities or final set agreement.

The start t0 is independently established definitive abandonment (complete transport close/reset, not input EOF alone), explicit operator termination/shutdown, or the configured command/connection deadline. The deadline cannot be extended by cleanup retries. By t0+1 s stop new workload admission, withdraw permission for new server-granted actions and request authorized whole-workload termination. These are separately visible actions; withdrawing a grant or successfully sending a termination request does not prove process death or reverse external file/network effects already committed. New server grants are withdrawn; the selected account’s OS permissions on already-running pending descendants are not magically revoked. Such work can still have account-authorized effects until actual termination. Requests already sent to external programs/services and effects outside the descendant/handle/resource boundary are not promised rolled back or globally cleaned up. Normal workload completion is independently observed zero live descendants, zero workload resident charge, zero workload-owned open handles/active I/O and release of server-owned PTY/output/pending data. Passive kernel transport/cache retention is a separate observed and still-charged host quantity, not an additional live workload grant or a claim all OS state vanished. Ordinary kernel cache/transport retention not attributable to live workload execution is reported separately within the existing finite host/transport envelope, retaining its charge until actual release; neither process residency alone nor a zero client count proves completion.

For the predeclared normal cohort, at least 99of100 trials must complete by t0+5 s, and every trial by t0+30 s. Any ordinary in-envelope trial past30 s fails; more than one past5 s fails the observed99% target. A late trial never moves to the exceptional population after its outcome. Independent observation uses upper-bound timestamps including its sampling/clock error; a completion merely inferred between polls cannot be rounded earlier. A completion by exactly the bound passes that non-strict boundary. The requirement is an empirical qualification target for the defined cohort, not99% confidence that99% of arbitrary future jobs finish.

By t0+30 s **every** case must either have independently established full completion or an operator-visible pending-cleanup record naming cause evidence (or unknown), retained authority, remaining work/resource charges, elapsed time, next observation/retry and responsible owner. Pending is not successful termination. The exceptional fault cohort is selected before execution using independently recorded injected kernel/device-progress or authority-observer faults; its all-case escalation/accounting/continued-observation obligations remain mandatory. An unexplained normal delay, resource-bound breach or missing platform authority is a failure/unknown cause, not an exceptional waiver. Do not promise eventual completion without restored platform progress.

Only one workload grant slot exists, counting a running **or pending canceled** workload and all its descendants. A slot is reusable only after observed termination and reclamation, including after a channel closes or its transport disconnects. A pending job blocks new execution/authenticated grants; bounded preauth refusal/control remains available. No replacement job, transport, restarted daemon, timer expiry or new record may clear its charge. Operator transfer of responsibility requires explicit acknowledgement and preserved charges; automatic reboot, new host/deployment and unbounded replacement are not authorized remedies.

The job envelope is at most 64 tasks including threads,32 descriptors per workload process and 2048aggregate workload descriptors and 128 MiB/512 MiB/256 MiB attributable resident workload memory in F/M/P, all **subsets** of the target's total host/service limits, not additions. Workload task/descriptor/CPU/memory authority must remain effective after detachment and while pending. At most one 16 KiB current pending-work record and a64 KiB/64-entry bounded diagnostic history are retained; overwriting old diagnostic history must not lose the live job identity, charges or monotonic retry/failure counters. Exhaustion refuses new work before effects, without process death. Accounting unavailable or escaped work is an assurance failure, never presumed zero.

Schedule one independent termination/resource observation each second through 30 s and each 5 s thereafter while pending, with no extra busy-loop attempts. Each attempt is capped at 100ms wall time,10ms attributable CPU and 2 KiB diagnostic contribution within retained-log bounds; over-budget observation is diagnosed and new work stays blocked. Authorized whole-workload termination requests occur at t0,2 s,5 s if still pending, then once per 60 s while still authorized and pending, with no additional retries between those times. Each request is bound to the same independently identified workload authority, never recycled numeric process identity. Missing permission/error is reported; no escalation grants new privileges. Observation/retry continues under that finite slot and per-attempt budget until completion or explicit accepted handover. Missed/over-budget scheduled attempts are reported as failures/unknown observation, not treated as continued successful monitoring. The supported fault envelope keeps the daemon/control observer schedulable while a workload may stall; a whole-host scheduling/power failure cannot be promised an on-host report by 30 s and is separately recorded by the outside observer, with no backdated success. A permanently stalled platform can prevent eventual completion; the contract promises continuing bounded responsibility and honest pending state, not a physically impossible deadline. A future fault controller releases planned reversible stalls at 45 s; an unexpected unreleasable fault stops qualification with ownership retained.

The 100 normal trials all use the declared Pprofile and are ten per predeclared class: ordinary command exit, input-EOF with final output, PTY close, CPU-active cancellation, backpressured output, detached descendants, ignored cooperative termination, valid delayed termination, concurrent forks within the64 task limit, and explicit operator termination following revocation or shutdown. All use synthetic harmless commands and the same fixed account/envelope. Distinct mandatory fault cases cover independently controlled nonprogress, failed termination authority observation and unavailable resource observation, with ordinary near-neighbors and release/recovery. Fault injection is future evaluation tooling, not a production provider or a runtime action performed here.

## Numeric profiles and accounting

KiB = 1024 bytes, MiB = 1048576 bytes. One service across all listeners, not per listener. A connection transitioning from preauth to authenticated leaves preauth and occupies authenticated capacity; it is never counted as two retained transports.

| Profile | F functional | M expanded preauthentication | P active work |
| --- | --- | --- | --- |
| Total transports / preauth / authenticated transports / active session channels | 65 / 64 / 1 / 1 | 1025 / 1024 / 1 / 1 | 129 / 128 / 1 / 1 |
| Whole-service resident ceiling / attributable host envelope | 512 MiB / 1 GiB | 2 GiB / 4 GiB | 1 GiB / 2 GiB |
| Descriptor allowance / reserve beyond clients and workload/PTY descriptors | 4096 / 64 | 4096 / 128 | 4096 / 128 |

Identification line at most 255 bytes including terminator; uncompressed SSH packet payload at most 64 KiB; packet total including length, padding and MAC at most 66 KiB. Channel data item at most 32768 bytes, initial channel credit 1 MiB and unsigned protocol credit never wraps. A 32768-byte channel data item plus its nine-byte message envelope fits 64 KiB; maximum 64 KiB packet payload plus four-byte length, one-byte padding length, at most 255 padding bytes and 32-byte MAC is 65828 bytes, below 66 KiB. Fragmented maximum items cannot be rejected merely because a consumer omitted framing overhead.

Per preauth transport cumulative input at most 256 KiB including framing, output at most 256 KiB, six signed authentication failures and eight key queries. Key blob 16 KiB, signature 8 KiB, username 256 bytes, one operator authorization file at most 64 KiB/64 keys; malformed or overlong authorization record is rejected as a whole, not split into another key/option. Retained preauth input/output total at most 512 KiB per peer; entire M preauth retention at most 512 MiB. Command request 8192 bytes; PTY terminal name 64 bytes, mode data 4096 bytes, character dimensions 1–512 each, pixel dimensions 0–65535. Environment requests fail. Per command stdin 8 MiB, combined stdout/stderr 8 MiB; authenticated-transport cumulative channel content across every serial channel at most 64 MiB each direction, excluding separately bounded SSH framing. Pending authenticated output at most 16 MiB, diagnostics retention 16 MiB. Operator must expose these finite settings without required upstream syntax.

Authenticated-connection total lifetime is one hour from authentication success; it never extends because a command, rekey or keepalive made progress. Per authenticated transport, non-data protocol/control payload totals at most 1 MiB and 4096 messages, including ignored/debug/global/window/rekey requests and their replies, after authentication success through teardown, counting both directions together; channel DATA/EXTENDED_DATA content messages use the separate data/encoded budgets; at most 128 such messages in any rolling second and at most 16 rekey exchanges in the hour: the first KEXINIT for a new exchange consumes one initiation, its response is part of that exchange, and all individual messages still consume control budgets. Initial KEX is setup, not a rekey. All encrypted input/output including packet framing, padding, integrity and control traffic is at most 128 MiB per direction over the connection. At the accepted message that would exceed a limit, emit the protocol-appropriate bounded refusal/disconnect without executing its requested action; do not insert a channel reply into another channel. This provides finite work accounting for many tiny control/data packets as well as content. One legal 8 MiB command transfer at normal 32768-byte channel items, full standard framing and permitted control traffic fits well below 128 MiB; 64 MiB cumulative content and 128 MiB encoded bounds need not both be reached with one-byte protocol packets. Network fragmentation alone does not consume an additional protocol-message charge. Independent A-S-01/04/11/12 scenarios exercise exact/cumulative/rate limits, valid large transfer, over-limit control churn and five-second recovery. These numbers are original provisional policy under DESIGN-03.

Admission to server identification at most one second; initial KEX five seconds from transport admission; authentication grace 15 seconds from admission, not reset by packet drips; ordinary authenticated request reply one second from complete message; channel no-progress timeout 30 seconds; command or terminal maximum lifetime one hour from successful exec/shell acceptance; authenticated idle 300 seconds, reset by valid useful application activity only. Rekey before 1 GiB encrypted content or one hour under the same keys, or earlier standard key-use bound; finish requested rekey within five seconds, with bounded paused application traffic. Cleanup follows the separate1 s/5 s/30 s actions, normal cohort and pending responsibility above; shutdown stops admission/drains or reports pending by 30 s. Ordinary overload release to login/control is within 5 s when the single grant is free; a genuinely pending canceled job keeps execution closed and reports its cause rather than falsely promising a replacement login. A full one-hour authenticated-transport terminal-lifecycle observation is a required deterministic future case: the terminal must remain useful up to the earlier transport deadline. Because exec/shell acceptance follows authentication, its own default one-hour command bound is dominated by the connection deadline; it does not promise an extra hour or a full hour after shell acceptance. A shorter configured command deadline has separate deterministic cases.

Combined-limit validation rejects a packet cap too small for the permitted channel data/envelope, preauth totals exceeding host allowance, authenticated/session count above the one-user profile, missing descriptor reserve or incompatible byte/lifetime settings atomically. M client descriptors1025 plus 2048aggregate workload descriptors (already derived from 32 per process and 64 tasks), five service-side workload/PTY descriptors and 128reserve =3206, below 4096. F65+2048+5+64=2182 and P129+2048+5+128=2310 also fit4096. These descriptor allowances are revised draft proposals; the old smaller F/P allowances did not cover the finite descendant envelope. This arithmetic does not measure allocator/OS resource cost. A legal maximum transfer must be admitted when otherwise idle; all peers' maxima need not coexist. Excess arrivals get bounded admission refusal without killing the service or granting authority. SSH's preauth profile is not copied to web or Redis.
