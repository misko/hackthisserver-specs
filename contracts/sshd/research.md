## Approaches and capabilities

### Retained approach comparison

Identity: sshd-design-r2. Nonnormative; no runtime observations. All options must meet the identical proposed public command/terminal/one-user authority contract, exact foundation, owned crypto, denial, cancellation and resource gates. Criteria declared before ranking: security reviewability, authority/failure ownership, full-envelope efficiency/resource plausibility, independent testability, compatible reuse, maintenance and meaningful source independence. Failing a hard gate is ineligible.

| Approach | Consequential high-level choice | Authority, resource, cancellation and review implications | Screen/rank |
| --- | --- | --- | --- |
| Reserved state allowances | Keep the declared authenticated workload's required resource allowance unavailable to preauthentication work even while no user is active. | Clear ownership and fewer resource-reclamation races; unused authenticated allowance may lower preauth capacity within the equal host envelope. Authority, packet validation and cleanup remain mandatory. | Conditionally eligible, preferred for simpler security/failure review; full M/efficiency feasibility remains unmeasured. |
| Unified admission allowance | Admit all states against one shared finite resource envelope without a standing authenticated-state reservation; retain each public state's cap and legitimate-control promise through admission decisions. | Potentially less idle reservation but more verification of legitimate progress when preauth work is already admitted. Cannot use denial of all legitimate work to satisfy the contract. | Conditionally eligible, second; fewer unused resources is a hypothesis, review of shared pressure is harder. |
| Borrowable state allowances | Keep distinct state allowances but permit idle authenticated allowance to be lent to preauth work, with bounded reclamation before the next authenticated transition/use. | Potentially improves idle use while retaining declared ownership; lending/reclamation races, already admitted preauth work and transition deadlines need additional evidence. | Conditionally eligible, third; most transition assumptions. No allocation algorithm or fixed process layout is prescribed. |

Pairwise: reserved versus unified changes whether idle authenticated allowance is unavailable to preauth work, trading potential capacity for isolation-review simplicity. Reserved versus borrowable changes whether that allowance can be lent at all, adding reclamation/cancellation evidence. Unified versus borrowable changes whether a borrowed state's claim must be explicitly reclaimed under a finite transition boundary, adding ownership states while potentially limiting starvation. A design must choose one of these incompatible allowance policies for a given resource/profile; merely saying every approach bounds work, authenticates users and preserves useful progress would supply no alternatives. None changes public caps or grants additional authority. An earlier authorization-lifetime comparison was challenged as insufficiently distinct for the single-session profile and replaced here before the design checkpoint. The design preference remains nonnormative; empirical capacity, cleanup or efficiency failure reopens it.

[RFC 4251 section 4.2](https://www.rfc-editor.org/rfc/rfc4251.html#section-4.2) distinguishes mandatory implementation from local permission to use an algorithm. Section 4.3 provides local algorithm policy. Therefore the modern negotiation allowlist need not enable obsolete algorithms to retain mandatory implementation coverage. RFC 4253 still lists 3des-cbc, hmac-sha1 and ssh-dss as required; the inspected updates do not remove those particular requirements. These facts resolve the research question; they do not qualify any implementation.

Proposed amendment MTI-P-01: retain the existing modern-only service negotiation policy, and explicitly require owned, bounded implementations of the remaining RFC 4253 mandatory algorithms as a separate SSH component profile.
