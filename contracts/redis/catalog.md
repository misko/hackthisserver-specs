# Finite Redis command catalog

Identity: redis-catalog-r2. Normative draft proposal, not final scope agreement. Document agreement Draft; every R-CMD requirement is Untested. Owner: future Redis maintainer. Protocol versions RESP2 and RESP3 are accepted user scope. Exact 60-command catalog, option subsets and finite limits are original policy proposals. Prerequisite: redis-r2, which owns state, authority, time, output and durability boundaries. No configuration syntax or implementation algorithm is prescribed.

Every row is one stable command requirement R-CMD-01 through R-CMD-60 and maps to the corresponding A-CMD scenario in acceptance.md and task R-T2/R-T4. Initial state is authenticated default account, valid F/M/P profile and controlled keyspace with missing/string/list/hash/set/zset fixtures. Exercise success, missing key, wrong type, duplicate arguments, binary values, minimum/maximum lengths, malformed and overflow variants, and a valid neighboring operation. Observe exact RESP types/bytes and independent cross-client state; forbid partial changes on parsing/admission errors, cross-account effects, remote execution/egress or outside storage writes. Ordinary command deadline is two seconds; recovery five seconds after release. Blocking operations and durable acknowledgement use the specific contract deadlines. All numeric bounds include framing/replies as stated in redis-r2.

Command names and option tokens are ASCII case-insensitive; keys, fields, members, passwords and values are opaque binary. Commands arrive as nonempty arrays of nonnull blob strings in both protocols. Unknown commands/options/arity yield ERR and no command effects; an error while queueing marks the transaction dirty. WRONGTYPE is the type error except explicitly documented MGET behavior. Integer arguments and stored integer strings use signed decimal 64-bit range with no whitespace, plus sign, redundant leading zeros, negative zero or overflow; the sole zero spelling is one zero digit. Scores use signed decimal binary64, optional decimal point/exponent and signed infinity tokens; reject NaN, whitespace, unsupported hex forms and overflow without effects. No array ordering is promised for unordered hash/set results, but membership and multiplicity are exact. Empty collection keys are absent once their last element is removed. Expiry is preserved on in-place mutations and cleared on replacement except explicit KEEPTTL. These defaults apply to every row, avoiding omitted recovery/error fields.

Primary command metadata is pinned to Redis 8.10.1 revision 3399357e7c17b668289386b8a15a3037bc4527b1; each link is provenance, never a production design or permission to port its tests. All 60 argument/reply schemas were retrieved and reviewed during this run. Public reply behavior was cross-checked in selected source where metadata was ambiguous or contradictory: counted SPOP uses RESP2 array/RESP3 set; TYPE missing key is the simple string none, despite a null entry in the schema; SETNX returns one on creation and zero when present, despite reversed descriptive schema entries. TTL rounds nonnegative remaining milliseconds to nearest second with half seconds rounded upward. These are researched observable facts, not required internal formulas. A finite compatible catalog does not claim all Redis commands or every option of a named command.
