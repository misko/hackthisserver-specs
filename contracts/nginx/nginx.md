# nginx public service contract

Identity: nginx-r2. Document agreement: Draft. Implementation evidence: Untested for every requirement. This is a proposed fresh replacement profile, not a claim of full nginx compatibility or preserved deployment. Product owner: user. Requirement owner NGX-01 through NGX-16: future web maintainer. Each NGX number maps to A-NGX with the same number in [acceptance and qualification](acceptance.md), and to its task in [tasks](acceptance.md#future-tasks). All settings below are proposed original policy except the accepted publication boundary, recipe requirements and cited mandatory wire behavior. Pending decisions: [ledger](../decisions.md).

Intended users are anonymous HTTP readers and applications using a small fixed-destination reverse proxy. Proposed environment is Linux x86-64 ELF, with operator-provided read-only published content and TLS identity, controlled origin endpoints and no deployment-specific exception. Required service capabilities are static GET/HEAD, validators, a single byte range, fixed-route HTTP proxying and TLS 1.3 HTTPS. Compatibility concerns the specified wire behavior and operator-visible settings, not nginx configuration, CLI syntax, modules or storage internals. The proposed reference is NGINX Open Source 1.30.6 at fb0e979c6dd63c018958b41eeb844947c5c21264; exact comparison identity must remain fixed before future measurements.

## Scope and authority

| Required | Excluded and observable outcome |
| --- | --- |
| HTTP/1.1 request and response semantics; multiple requests per connection; bounded pipelining with ordered responses | HTTP/2, HTTP/3 and SPDY: no advertised ALPN or UDP listener; an unsupported major version receives 505 when an HTTP response is possible, otherwise bounded close. A syntactically valid HTTP/1.0 request receives the local profile's403 with compatible Content-Length framing and close, without Transfer-Encoding or effects; it is not mislabeled malformed syntax or a different major version. Higher HTTP/1 minor versions are processed as HTTP/1.1 under RFC 9110 section 2.5. |
| Static GET/HEAD and fixed-path route selection | File writes, directory listing, SSI, script execution, DAV, content transformations, dynamic modules and expression language: no execution or write path; disallowed known method receives 405 with Allow, unknown unimplemented method 501. |
| Proxy GET, HEAD, POST, PUT, PATCH, DELETE and OPTIONS to operator-selected numeric endpoints | Forward proxy, CONNECT, protocol upgrades, dynamic DNS or client-selected egress: valid CONNECT gets 405 and close; malformed CONNECT authority/port gets 400 and close; upgrade gets 501 and close. Never open a tunnel or process trailing optimistic bytes as another request. |
| TLS 1.3 server profile W13, operator-installed certificates and identity reload | TLS 1.2 for this web profile, early data, session tickets/resumption, client-certificate login and automatic certificate issuance: no negotiation/use; unsupported negotiation fails before HTTP authority. |
| Startup, atomic reload, bounded shutdown, diagnostics and recovery | Remote administration and deployment orchestration: no remote settings or control endpoint. |

The operator is trusted to choose roots, identities and endpoints; remote clients, intermediaries and origin responses are hostile. A malicious kernel or administrator with full OS authority is outside the boundary. The server obtains no authority to execute commands, alter published content, read outside its roots or contact unconfigured destinations. Proxy-origin effects authorized by an accepted request cannot be rolled back merely because the client disappears.

The optional Incremental field defined in RFC 10036 is outside this profile's claimed capabilities. Treat it as an opaque permitted end-to-end field and retain ordinary finite exchange limits; do not advertise incremental-delivery support. If a future revision implements it, its positive value must receive actual incremental forwarding or the RFC's explicit refusal semantics. Ordinary HTTP continuation/informational progress remains mandatory here regardless of that optional field.

## Finite profiles and accounting

MiB means 1,048,576 bytes; KiB means 1,024 bytes. Caps apply to one entire service across listeners, not independently per listener. A connection moves between states and is counted once in total transport capacity; handshake and active counts are subsets. Payload limits count decoded application content. Framing caps count HTTP plaintext including framing, independently of TLS record overhead. Retained output remains charged until definitively released even when delivered to transport but unread by the receiving application.

| --- | --- | --- | --- |
| Transport connections / pending TLS handshakes / active requests / active origins | 64 / 16 / 16 / 16 | 2048 / 128 / 64 / 64 | 512 / 64 / 64 / 64 |
| Queued fully framed requests, entire service | 64 | 2048 | 512 |
| Pipeline requests per connection | 8 | 8 | 8 |
| Whole-service resident ceiling / attributable host envelope | 512 MiB / 1 GiB | 4 GiB / 8 GiB | 2 GiB / 4 GiB |
| Descriptor allowance / service reserve beyond client+origin descriptors | 256 / 64 | 8192 / 128 | 4096 / 128 |

All profiles: request target 8192 bytes; full request header section including start line 32768 bytes, 100 fields, single field 8192 bytes; request content 1 MiB; additional request chunk/trailer framing 1 MiB; origin response content and static representation 8 MiB; full origin response fields 32768 bytes; origin chunk/trailer overhead 2 MiB; client serialized response content plus all HTTP framing at most 9 MiB. Trailer sections fit the same field-section bounds and cannot alter framing, routing, authentication or content length. Queue admission includes body/reply reservations and metadata, not just socket count. Temporary content storage is at most 256 MiB in F and 1 GiB in M/P, with no escape outside an operator-selected private area. Retained diagnostic storage is at most 16 MiB; diagnostics cannot block service indefinitely.

Deadlines start at observable events: TLS admission to authentication 5 seconds; first complete request headers5 seconds from transport admission on clear HTTP or TLS handshake completion on HTTPS (silence cannot defer this initial deadline); subsequent request first byte to complete headers5 seconds; final headers to complete request content 10 seconds; origin connection attempt 3 seconds; accepted complete headers to complete exchange 30 seconds; no client/origin progress 5 seconds while active; idle keepalive 60 seconds from last complete response; shutdown drain 30 seconds; overload release to ordinary successful control 5 seconds. Progress never extends the absolute exchange or framing deadlines. A zero-length body does not create an indefinite wait. At least one ordinary small request from an independent client must finish in 2 seconds during the declared matched overload scenario when admitted under the legitimate-control allowance.

Operator validation rejects zero/unbounded settings, a frame cap smaller than its permitted content plus mandatory framing, output cap smaller than a legal maximum fixed-length response, active-origin count above descriptor headroom, or a reservation envelope that cannot admit one legal maximum operation. It does not promise all per-client maxima coexist: bounded overload may refuse before effects. In F, 16 maximum request/response pairs require 144 MiB content plus at most 1 MiB fields, leaving a stated 367 MiB for transport, cryptography, metadata, diagnostics and implementation overhead. This is feasibility accounting, not measured memory. In M, 2048 client plus 64 origin descriptors plus 128 reserve is 2240, below 8192. The future evaluator must measure all actual resource costs.

## Routing, representation and response details

Operator routes are a finite table of exact authorities and path-segment prefixes, each selecting a static root or one fixed origin. DNS host comparison is ASCII case-insensitive with default scheme port equivalence; no wildcard/expression route is implied. Longest complete segment-prefix wins; duplicate/equally specific conflicting routes invalidate the whole configuration. Missing route yields 404 without origin contact. For origin-form, valid Host supplies authority; for absolute-form, its scheme/authority controls and Host cannot override it. Userinfo, empty/invalid port, fragment, malformed percent encoding, literal controls/space, raw non-ASCII target octets and malformed authority get 400/close. Percent decoding occurs once for static path selection; reject decoded NUL, backslash, slash encoded inside a segment and literal/decoded dot or dot-dot segments, including repeated encodings that would change meaning if decoded again. Repeated slash policy is rejection with 400. Query bytes remain opaque and are never filesystem path bytes; proxy forwards the accepted origin-form path/query without client-selected endpoint authority. These are stricter original path-profile choices, not all nginx defaults. Valid ordinary encoded filename bytes remain opaque after the declared decode and never cause script evaluation.

A static root request resolves only its exact relative regular file; no implicit index/autoindex/redirect is promised. Successful static representations supply accurate Content-Length, Content-Type from an operator-selected finite MIME mapping (otherwise application/octet-stream), Date from trusted operator clock, a strong opaque ETag tied to the published complete version, Last-Modified and Accept-Ranges: bytes. HEAD metadata matches GET for the selected version without content; 304/204/1xx obey their content/length restrictions. Conditional precedence is If-Match, then If-Unmodified-Since when If-Match absent, then If-None-Match, then If-Modified-Since when If-None-Match absent, followed by applicable If-Range/range evaluation. Strong/weak comparisons and invalid dates follow RFC 9110. Range supports the verified-erratum optional whitespace after the equals sign, then one inclusive/suffix byte range clipped at representation length; multiple or unknown-unit range may be ignored with 200, never partially combined arithmetic. Origin responses retain permitted end-to-end status/fields, with exact framing normalization and hop-specific removal. The proxy adds its declared Via identity, bounds intermediary loops and never follows origin redirects or treats origin control-looking fields as local instructions. Origin-supplied redirects are ordinary client-visible fields. Local errors are finite responses with accurate framing; no local error is injected after final-response commitment.

### Continuing delivery cleanup profile

Under stream-r2, definitively abandoned delivery/wait work keeps its original finite connection, active/queue, byte, storage and host charges until independent observation establishes release. Missing the promised5snormal release/recovery is a failed absolute gate, not permission to erase charges. A pending item occupies its original admission allowance; replacement work must fit the remaining unchanged limits, so repeated failures cannot create unlimited hidden work. Report pending identity/cause(or unknown), current charges, owner and next due observation through the bounded diagnostic interface. No automatic restart, host replacement or new authority clears it.

Schedule one observation each 1 s through 30 s, then each 5 s while pending; each attempt≤100mswall,10msCPU,2KiB log contribution within 16MiB retained diagnostics. One bounded pending record≤16 KiB per existing charged connection/work item, never beyond original connection/active/queue caps; records are part of existing resident envelope, not extra admission. Authorized cancellation/close requests occur at definitive abandonment,2 s,5 s, then once each 60 s while needed/authorized. Missed/over-budget attempts are visible failures/unknown observations. Continue responsibility until observed reclamation or explicit accepted handover; no promised eventual completion without platform progress.

Normal application completion, closed handles and full attributable OS reclamation are separate observations. Passive kernel transport/cache retention may remain after application release; independently report its bytes/state/lifetime and keep it charged to the finite host envelope/admission accounting, never label unknown active I/O as passive or claim full reclamation solely from process residency. An unavailable OS observer leaves that assurance Inconclusive. Whole-host loss of progress cannot promise a timed on-host report; an outside observer records it, with no backdated success. These are clarified delivery-accounting duties, not an SSH account/job policy.

Initial idle accounting starts at transport admission/TLS completion as applicable; the first-header5sdeadline is stricter than idle keepalive60 s. After a completed response, idle60sruns from that response and progress does not extend an already-started5sheader deadline. A-NGX-02/12include a wholly silent initial peer and a late first-byte neighbor. This is explicit timer-origin clarification in the proposed r2profile.
